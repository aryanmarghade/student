3. ENTRY POINTS & HOW THE APP BOOTS
================================================================================

STEP 1 -> npm run dev  ->  runs: tsx server.ts

STEP 2 -> server.ts (root):
  - Loads .env via dotenv
  - Connects to PostgreSQL (calls initializeDatabase() from server/db.ts)
  - Mounts Express API routes:
      /api/auth      -> server/routes/auth-routes.ts
      /api/admin     -> server/routes/admin-routes.ts
      /api/teacher   -> server/routes/teacher-routes.ts
      /api/student   -> server/routes/student-routes.ts
  - In DEV mode: uses Vite as middleware (HMR, SPA serving)
  - In PROD mode: serves /dist as static files
  - Listens on PORT 3000

STEP 3 -> Browser loads index.html -> /src/main.tsx -> /src/App.tsx

STEP 4 -> App.tsx:
  - Checks localStorage for JWT token
  - Calls GET /api/auth/me to validate session
  - Shows LoginView if not logged in
  - Shows AdminView, TeacherView, or StudentView based on user.role

4. DATABASE (db/ folder)
================================================================================

FILE: db/schema.sql  [MOST IMPORTANT DB FILE]
  - Defines ALL tables with IF NOT EXISTS (idempotent - safe to re-run)
  - Contains ALTER TABLE statements for columns added after initial release

  TABLE: users
    id, email, password_hash, role (admin|teacher|student),
    full_name, is_active, must_reset_password, created_at
    Purpose: ALL user accounts regardless of role

  TABLE: colleges
    id, name, code, address, created_at

  TABLE: departments
    id, college_id (FK->colleges), name, code, created_at
    Examples: Computer Science, Electronics, Mechanical

  TABLE: academic_years
    id, year_name (e.g. "2024-2025"), is_current, created_at

  TABLE: semesters
    id, academic_year_id, semester_number, name (e.g. "Semester 3"), is_active, created_at

  TABLE: classes
    id, department_id, academic_year_id,
    name (e.g. "CS-3A"), year (1-4), section (A/B/C), created_at
    Purpose: A class is a specific group of students

  TABLE: subjects
    id, department_id, name, code (e.g. "CS301"), max_marks (default 100), created_at

  TABLE: students
    id, user_id (FK->users UNIQUE), roll_number, class_id, department_id,
    linkedin_url, github_url, hackerrank_url, portfolio_url,
    profile_photo_url, resume_url, bio, profile_strength (default 20),
    github_data (JSONB), github_synced_at, created_at
    Purpose: Extended student-specific profile linked to users table

  TABLE: student_documents
    id, student_id, doc_type, file_url, file_name,
    parsed_headings (JSONB), status, title, description, category, created_at
    Purpose: Resumes, certificates, assignments, etc. uploaded by student

  TABLE: projects
    id, student_id, title, description, technologies (JSONB array),
    github_url, live_url, date, team_members (JSONB), image_url,
    verification_status, created_at

  TABLE: achievements
    id, student_id, title, description, organization, date, link,
    certificate_url, verification_status, created_at

  TABLE: certifications
    id, student_id, name, issuer, issue_date, credential_id,
    credential_url, certificate_url, verification_status, created_at

  TABLE: hackathons
    id, student_id, name, organizer, date, position_result, team_name,
    project_name, project_description, github_url, demo_url,
    certificate_url, verification_status, created_at

  TABLE: events
    id, name, description, organizer, event_date, registration_deadline,
    location, registration_link, banner_url, eligibility,
    status (upcoming|ongoing|completed), created_by, created_at

  TABLE: teacher_class_assignments  [THE AUTH TABLE]
    id, teacher_user_id (FK->users), class_id, subject_id, semester_id,
    status (active|past), created_at
    Purpose: A teacher can ONLY access a class+subject+semester if a row exists here

  TABLE: marks
    id, student_id, class_id, subject_id, semester_id, teacher_user_id,
    exam_type, marks_obtained, max_marks, created_at
    Unique constraint: (student_id, class_id, subject_id, semester_id, exam_type)

  TABLE: assessment_definitions
    id, class_id, subject_id, semester_id, teacher_user_id, title,
    max_marks, assessment_type (Internal|Mid Sem|Final|Assignment|Practical|Other),
    status (active|archived), created_at

  TABLE: marksheets
    id, student_id, semester_id, file_url, file_name, sgpa, cgpa,
    uploaded_by, created_at
    Purpose: Official university marksheet PDFs uploaded by admin

  TABLE: notifications
    id, title, body, target_role (all|all_students|all_teachers|class),
    target_class_id, file_url, created_by, created_at

  TABLE: notification_reads
    id, notification_id, user_id, read_at

  TABLE: ai_query_logs
    id, user_id, query_text, resolved_intent, response_summary,
    tool_calls (JSONB), created_at
    Purpose: Full audit trail of all AI assistant queries

  TABLE: audit_logs
    id, user_id, action, entity_type, entity_id, details, created_at

  TABLE: posts
    id, student_id, title, description, category, tags (JSONB), external_link, created_at

  TABLE: post_attachments
    id, post_id, file_url, file_name, file_type, created_at

FILE: db/seed.sql
  Seeds: colleges, departments, academic years, semesters, classes, subjects,
  demo users, teacher assignments, student records, sample marks, notifications
  All demo passwords hash to "password123"

FILE: db/seed-qa.sql
  QA-specific seed data. Used by initializeDatabase() on every boot.
  Ensures required demo users always exist.

FILE: db/cleanup-legacy.sql
  Removes old/legacy seed records replaced by QA seed migration.

5. BACKEND SERVER (server/ folder)
================================================================================

FILE: server.ts  (ROOT - ENTRY POINT)
  - Express app on port 3000
  - Calls initializeDatabase() before serving
  - Mounts: /api/auth, /api/admin, /api/teacher, /api/student
  - Integrates Vite as dev middleware

FILE: server/db.ts  [DATABASE LAYER]
  - PostgreSQL connection pool via DATABASE_URL
  - Exports: pool, query<T>(), logActivity(), initializeDatabase(), id()
  - initializeDatabase(): runs schema.sql + seed-qa.sql + cleanup on startup
  - id(prefix): generates IDs like "user_1718000000000_abc123"

FILE: server/auth.ts  [AUTH MIDDLEWARE]
  - generateToken(user, student?): creates 7-day JWT
  - hashPassword(value) / comparePassword(value, hash): bcrypt helpers
  - requireAuth middleware: validates Bearer token, checks user active
  - requireRole(...roles): enforces role-based access
  - verifyTeacherClassScope(): checks teacher_class_assignments table
  - rateLimit(): in-memory per-IP rate limiter

FILE: server/ai-assistant.ts  [AI MODULE - used by current routes]
  - buildScopedContext(user): queries DB for role-appropriate context
      admin -> institution stats
      teacher -> their active assignments + averages
      student -> own profile, marks, CGPA
  - handleAiQuery(user, queryText): sends to Gemini if key set, else returns raw DB data
  - Logs every query to ai_query_logs

FILE: server/ai.ts  [LEGACY AI MODULE - used by server/index.ts only]
  - Full function calling with tool declarations:
    get_class_topper, get_student_average, predict_next_score,
    get_struggling_students, get_student_academic_summary

FILE: server/analytics.ts  [MATH UTILITIES]
  - linearRegression(points): slope, intercept, R-squared, predicted next value
  - median(values): median of number array
  - standardDeviation(values): population std deviation

FILE: server/documents.ts / server/resume-parser.ts  [RESUME PARSING]
  - parseResume(fileBuffer, mimeType): heuristic section extractor
  - Extracts: Education, Skills, Projects, Experience, Certifications, Summary
  - Stored in student_documents.parsed_headings as JSONB

FILE: server/index.ts  [LEGACY SERVER - 1201 lines - NOT ACTIVE]
  - Alternate server on PORT 4000
  - Uses AWS S3 SDK for file storage
  - DO NOT use this - server.ts (root) is the entry point

11. HOW TO ADD NEW FEATURES
================================================================================

NEW API ENDPOINT:
  1. Add SQL in server/routes/{role}-routes.ts
  2. Add type in src/types.ts
  3. Add api.xxx() in src/lib/api.ts
  4. Call from src/views/{Role}View.tsx

NEW DATABASE TABLE:
  1. Add CREATE TABLE IF NOT EXISTS to db/schema.sql
  2. Add seed data to db/seed-qa.sql
  3. initializeDatabase() runs schema.sql on every boot (idempotent)

NEW ROLE PERMISSION:
  1. Update requireRole() in the route
  2. For teachers: call verifyTeacherClassScope()
  3. For students: always scope to req.user.student_id
