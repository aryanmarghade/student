1. SOURCE OF TRUTH & ARCHITECTURE OVERVIEW
=============================================================================
The contents of this file reflect the active source code, schema, and API endpoints.
The architecture consists of:
- Backend: Node.js/Express TypeScript backend running on port 3000 (`server.ts`).
- Frontend: React 19 SPA powered by Vite 6 with Tailwind CSS (`src/App.tsx`).
- Database: PostgreSQL (unified persistent relational source of truth).
- Authentication: Role-Based Access Control (RBAC) supporting 4 distinct user roles:
  1. System Administrator (`admin`)
  2. Faculty / Subject Teacher (`teacher`)
  3. Verified Student (`student`)
  4. Placement Officer (`placement`)

4. COMPLETE BACKEND FILE MAP
=============================================================================
[ ACTIVE BACKEND ]

server.ts
Purpose: Backend application entry point.
Responsibilities: Initializes Express, configures middleware (CORS, JSON parsing, logging), mounts routes (`/api/auth`, `/api/admin`, `/api/teacher`, `/api/student`, `/api/placement`), and handles static file serving.
Status: ACTIVE.

server/db.ts
Purpose: PostgreSQL database connector.
Responsibilities: Exports `query()` wrapper for `pg.Pool`, ID generator (`id()`), and `logActivity()` audit logger.
Status: ACTIVE.

server/auth.ts
Purpose: Authentication and Authorization service.
Responsibilities: JWT creation/validation, bcrypt password hashing, `requireAuth`, `requireRole('admin' | 'teacher' | 'student' | 'placement')` middleware, rate limiting.
Status: ACTIVE.

server/academic-service.ts
Purpose: Core academic computation engine.
Responsibilities: `calculateAcademicHistory()` and `calculateAcademicHistoryBulk()` computing SGPAs, CGPAs, percentages, backlogs history, and credit tracking.
Status: ACTIVE.

server/routes/admin-routes.ts
Purpose: Admin REST API.
Responsibilities:
- User management (students, faculty, placement officers).
- Academic structure (colleges, departments, academic years, semesters, classes, subjects).
- Teacher & Placement analytics visibility configuration (`/api/admin/teachers/:id/analytics-visibility`, `/api/admin/placement/:id/analytics-visibility`, `/api/admin/analytics-visibility/all`).
- Official marksheets bulk uploads (PDF/ZIP).
- External synchronization triggers (`/api/admin/github/sync`, `/api/admin/leetcode/sync`, `/api/admin/analytics/sync-all`).
- Notifications, audit logs, and student dossier access.
Status: ACTIVE.

server/routes/placement-routes.ts
Purpose: Placement REST API.
Responsibilities:
- `GET /api/placement/visibility`: Returns active visibility permissions for the logged-in placement officer.
- `GET /api/placement/dashboard`: Returns summary stats, year-wise and class-wise CGPA distributions, and enriched student directory filtered by visibility flags.
- `GET /api/placement/students/:studentId/full-profile`: Returns complete student dossier including academic history, external coding profiles, projects, hackathons, and documents.
Status: ACTIVE.

server/routes/teacher-routes.ts
Purpose: Faculty REST API.
Responsibilities:
- Class rosters and student academic records scoped strictly to `teacher_class_assignments`.
- Dynamic assessment definition and spreadsheet marks entry.
- Class academic performance charts, grade distributions, and linear regression analytics.
Status: ACTIVE.

server/routes/student-routes.ts
Purpose: Student REST API.
Responsibilities:
- Self profile management (portfolio, bio, links).
- Project portfolio, certifications, achievements, and hackathons submission.
- Marks, semester transcripts, documents vault, and notification reads.
Status: ACTIVE.

server/github-sync.ts
Purpose: GitHub Monthly Synchronization Service.
Responsibilities: Fetches public repositories, stars, forks, followers, and language statistics. Saves monthly snapshots idempotently into `student_github_snapshots`.
Status: ACTIVE.

server/leetcode-sync.ts
Purpose: LeetCode Synchronization & Live Profile Service.
Responsibilities: Queries LeetCode public GraphQL API for problem counts (easy/medium/hard) and global rank.
Status: ACTIVE.

server/linkedin-sync.ts & server/hackerrank-sync.ts
Purpose: LinkedIn & HackerRank sync service handlers.
Responsibilities: Verified profile URL resolution without fake scraping.
Status: ACTIVE.

server/ai-assistant.ts & server/ai.ts
Purpose: Gemini AI Academic Query Engine.
Responsibilities: Answers grounded academic queries using tool calls against the database schema.
Status: ACTIVE.

7. DATABASE SCHEMA & RBAC RELATIONSHIPS
=============================================================================
Core Tables:
1. `users`: id, email, password_hash, role ('admin'|'teacher'|'student'|'placement'), full_name, is_active, must_reset_password.
2. `colleges`, `departments`, `academic_years`, `semesters`, `classes`, `subjects`.
3. `students`: user_id, roll_number, class_id, department_id, github_url, linkedin_url, hackerrank_url, leetcode_url, github_data, hackerrank_data, leetcode_data, portfolio_url, resume_url, profile_strength.
4. `teacher_class_assignments`: teacher_user_id, class_id, subject_id, semester_id, status.
5. `assessment_definitions` & `marks`: exam_type, marks_obtained, max_marks.
6. `projects`, `achievements`, `certifications`, `hackathons`: student portfolio items with verification status.
7. `posts` & `post_attachments`: student showcase posts with rich media attachments.
8. `student_documents` & `marksheets`: uploaded document vault and official semester marksheets.
9. `teacher_analytics_visibility`: teacher_user_id, github_enabled, linkedin_enabled, hackerrank_enabled, leetcode_enabled, hackathon_enabled, academic_enabled.
10. `placement_analytics_visibility`: placement_user_id, github_enabled, linkedin_enabled, hackerrank_enabled, leetcode_enabled, hackathon_enabled, academic_enabled.
11. `student_github_snapshots`, `student_linkedin_snapshots`, `student_hackerrank_snapshots`, `student_leetcode_snapshots`.
12. `notifications`, `notification_reads`, `events`, `audit_logs`, `ai_query_logs`.
